# Implementation contract

React/Vite frontend uses shared/types.ts and shared/domain.ts. Node 24 TypeScript server uses Express + node:sqlite. Separate scheduler imports the server database and encrypted push storage. SQLite resides at DATA_DIR outside public; single server replica and persistent disk required. VAPID_PRIVATE_KEY, DATA_ENCRYPTION_KEY and SESSION_SECRET only on server.

API (same origin; credentials cookies): GET /api/health; POST /api/auth/register and /api/auth/login {email,password} -> {user}; GET /api/auth/me -> {user}; POST /api/auth/logout; GET /api/state -> {state,revision}; PUT /api/state {state,revision} -> {state,revision}, 409 on revision conflict. Browser mutations require X-Requested-With: salary-guardians and Origin when supplied must match PUBLIC_ORIGIN. GET /api/export -> JSON; DELETE /api/account {password} -> clears user data and cookie. Errors {error:string}. State server validates using shared/domain.ts and state write is atomic. Newly added expense IDs cause server last-expense activity updates. Root domain exports createInitialState, validateState, allocationTotal, variableSpent, salaryCycle, kstDate, loanBalance, fundBalance, missionDefinitions, cycleComparison.

Push API authenticated: GET /api/push/status -> PushStatus; POST /api/push/subscribe {subscription:{endpoint,keys:{p256dh,auth}}}; POST /api/push/unsubscribe {endpoint?:string,all?:boolean}; POST /api/push/test -> {queued:true}. Push enabled stored in state.config.push.enabled. A device permission grant subscribes then updates config enabled. Disabling notifications updates state and unsubscribes current device; all-device opt out option. No keys in browser except public VAPID. GET status never returns subscription endpoint/keys. Worker runs separately with npm run worker, invokes scheduler.tick() every 30 seconds. Subscription registration encrypts endpoint and keys at rest.

Frontend path routes use hash (#home,#expenses,#loan,#savings,#missions,#stats,#settings); notification links /#missions etc. SW /sw.js; manifest /manifest.webmanifest; push handler displays safe generic content; click opens/focuses same-origin hash route. Export per authenticated user. Deletion requires password confirmation and local cache cleanup. Offline authenticated GET state cache stored by user id; edits queue a latest snapshot; reconnect pushes expected revision and explicit conflict resolution rather than silent overwrite.

All amounts are integer KRW, each at most 100 billion, with at most 10,000 records per ledger to keep aggregate sums below JavaScript's integer precision bound. Boss repayments must supply actual principal and interest whose sum equals total; an unconfirmed other loan can have both fields null, or a confirmed split with the same equality. Only boss principal changes HP. Unknown big-purchase balance remains null until an explicit adjustment. Config allocation and six category budgets must balance. State PUT optionally carries captured userId; the frontend always supplies it so a queued request cannot accidentally apply to a different authenticated account.
