# 실제 iPhone 설치·푸시 테스트

2026-10-13 공개 서버 자동 검사([GitHub Actions](https://github.com/eujkim323030/money_safe/actions/runs/38361664194))는 통과했습니다. 임시 계정의 가입·저장·조회·내보내기·서버 푸시 설정과 계정 삭제를 확인했습니다. 사용자의 iPhone 앱에서는 가입 오류를 보고하여 현재 오류 문구를 확인 중이며, 실제 푸시 수신은 미검증입니다.

실제 HTTPS 앱은 **[https://money-safe.ttlikim16.workers.dev](https://money-safe.ttlikim16.workers.dev)**에 배포됐으며, 사용자가 홈 화면 설치 후 로그인 화면을 확인했습니다. 회원가입에는 **`서버 세션 비밀키 설정이 필요합니다.`** 오류가 발생했으나 이후 사용자가 초기화 완료 로그와 공개 `/api/auth/me`의 `로그인이 필요합니다.` 응답을 확인했습니다. 세션 키 검사는 통과하며 회원가입 재검증을 진행 중입니다. **알림 동의·구독·발송·앱 종료 상태의 실제 iPhone 수신은 아직 미검증**입니다. 서버 HTTP 201, 모의 Web Push 테스트, 브라우저 자동화만으로 수신이 입증되지 않습니다.

## 준비

- iOS/iPadOS 16.4 이상 iPhone, 인터넷 연결, Safari.
- [Cloudflare 초기 설정 복구](cloudflare.md)를 완료한 실제 앱 주소. 유효한 인증서, `manifest.webmanifest`, `/sw.js`, 같은 origin API가 제공되어야 합니다.
- 서버에 고정 VAPID 쌍/암호화키/세션 비밀, D1과 예약 Cron 설정. 현재 가입 오류를 먼저 해결합니다. Docker 대안에서는 [배포 절차](deploy.md)의 web와 worker를 실행합니다.
- 테스트 사용자 계정. 화면 잠금 상태의 알림도 볼 수 있도록 iPhone 설정에서 앱의 알림 허용·잠금화면·배너를 켭니다. 최초 검증은 집중 모드와 알림 요약을 해제해 표시 지연을 줄입니다.

## 홈 화면 설치와 사용자 동작에 의한 권한

1. iPhone Safari에서 실제 HTTPS 주소를 엽니다. 인증서 경고가 없어야 합니다.
2. Safari 공유 → **홈 화면에 추가** → 추가를 선택합니다.
3. Safari 탭을 닫고 홈 화면의 **월급수비대** 아이콘으로 실행합니다. 주소창 없는 설치 앱인지 확인합니다.
4. 로그인하거나 테스트 계정을 만듭니다. 설정 → 푸시 알림에서 **이 기기 알림 켜기**를 직접 누릅니다. 페이지 진입 시 자동으로 권한 대화상자가 나타나면 실패입니다.
5. iOS 권한 대화상자에서 허용합니다. 앱에서 서버 설정 상태와 구독 기기 수가 갱신되는지 확인합니다. 서버 비밀키/구독 endpoint는 UI에 나오면 안 됩니다.

거부했을 경우 앱은 거부 상태와 기기 설정 안내를 표시해야 합니다. 반복 요청으로 강제 허용하지 않습니다. iPhone 설정 → 알림 → 월급수비대에서 허용 후 앱을 다시 열고 **이 기기 알림 켜기**를 누릅니다. 설치 앱이 설정 목록에 없으면 iOS 버전, Safari 설치 경로, HTTPS, manifest/SW를 다시 확인합니다. 제거 후 재설치가 필요한 경우 로컬 오프라인 기록이 소실될 수 있으므로 먼저 동기화합니다.

## 종료 상태 테스트 푸시 (출시 필수)

1. 앱 설정에서 **테스트 푸시 보내기**를 누르고 서버가 전달 작업을 접수했는지 확인합니다.
2. 곧바로 홈 화면으로 나가 앱 전환기에서 앱 화면을 닫고 iPhone을 잠급니다. 테스트가 닫기 전에 도착했으면 종료 상태 증거가 아니므로 다시 수행합니다.
3. 아래 반복 가능 절차로 **앱이 이미 종료된 뒤** 서버에서 테스트를 다시 요청하면 타이밍을 분리할 수 있습니다. endpoint에 연결할 테스트 세션은 같은 사용자이되 세션/비밀번호를 터미널에 출력하지 않습니다.
4. worker 발송 시각과 잠금화면에 실제 표시된 알림 시각을 비교합니다. 집중 모드/요약 때문에 안 보이면 해당 기기 설정을 확인하고 다시 테스트합니다.
5. 알림을 눌렀을 때 설치 앱이 열리고 안내된 미션 또는 설정 화면으로 이동하는지 확인합니다. 다른 사용자의 정보 또는 외부 사이트를 열면 실패입니다.

### 이미 종료된 뒤 서버에서 테스트 요청

가장 간단한 방법은 두 번째 기기/브라우저에서 동일 테스트 사용자로 로그인한 뒤 iPhone 앱이 종료된 상태에서 **테스트 푸시 보내기**를 누르는 것입니다. 현재 구현의 테스트 알림은 그 사용자의 활성 구독들에 발송됩니다. iPhone 자체의 구독을 활성화해 둡니다. 민감한 거래를 테스트 본문에 넣지 않습니다.

명령행으로 검증할 경우에는 테스트 전용 계정과 보안 세션 쿠키를 사용하고 쿠키·비밀번호를 shell history/공유 로그에 노출하지 않아야 합니다. 일반 사용자에게 비밀 입력을 요구하는 복잡한 curl 절차보다 위 두 번째 브라우저 방법을 권장합니다.

Cloudflare Worker `money-safe`의 로그에서 같은 시간대의 발송을 확인합니다. CLI가 Cloudflare API에 접속 가능한 개발 환경에서는 다음 명령을 사용할 수 있습니다.

```sh
node scripts/cloudflare-cli.mjs tail money-safe
```

Docker 대안의 경우에는 `docker compose logs --since 10m worker`를 사용합니다. 현재 Codex 환경의 API 접근 차단 때문에 CLI 로그를 읽지 못하면 로그인한 Cloudflare 화면에서 확인한 안전한 결과 요약을 기록합니다. 비밀번호·세션 쿠키·API 토큰을 채팅으로 전달하지 않습니다.

`event=push_delivery`의 `deliveryId`, `timestamp`(UTC), `result=accepted`, `statusCode`와 기기 관찰을 함께 기록합니다. 로그의 `userId`는 개인 식별 정보일 수 있으므로 외부 공유 시 마스킹합니다. 알림 스크린샷에는 개인 거래·계정 정보가 없도록 합니다. APNs/Web Push 수락은 수신 증거가 아니며 표시 시간은 OS가 결정합니다.

## 예약, 조건, 중복과 해제 확인

아래 자동 테스트는 시간 제어로 수행될 수 있지만 실제 연결 확인은 별도입니다. 운영에서 다음 실제 일정에 확인하거나 **별도 테스트 계정**의 설정 시간을 다음 몇 분 뒤로 변경하여 worker 실행을 확인합니다. 운영 데이터나 서버 시스템 시각을 바꾸지 않습니다. 매월 25일/24일 및 일요일 조건 자체는 임의 시각 변경으로 모두 확인되지 않으므로 자동 테스트와 실제 해당 일정 결과를 구분합니다.

| 시나리오 | 실제 확인 절차 | 기대 결과 |
| --- | --- | --- |
| 월급 분배 | 25일 설정 시각에 앱 종료 상태 유지 | 일반적인 분배 미션 알림 1회 |
| 일요일 결산 | 일요일 설정 시각에 앱 종료 상태 유지 | 주간 결산 알림 1회 |
| 급여주기 종료 | 24일 설정 시각에 앱 종료 상태 유지 | 해당 주기 결산 알림 1회 |
| 80% 첫 도달 | 테스트 사용자 주기 지출을 기준 미만 → 80% 이상으로 저장 | 최초 도달 알림; 추가 지출/수정/재시작 후 같은 주기 재발송 없음 |
| 미기록 | 테스트 사용자 설정 기간 동안 동기화된 새 지출 없음 | 미기록 안내; 새 지출 이후 다음 기간을 다시 계산 |
| worker 재시작 | 테스트 작업 직후 worker 재시작 | 저장된 발송 이력 유지; 같은 일정 중복 억제 |
| 권한 거부 | 설치 앱에서 거부 | 설정 안내; 지원되지 않는 자동 재요청 없음 |
| 현재 기기 해제 | **이 기기 구독 해제** 선택 | 이 endpoint 제거 및 계정 예약 알림 끄기; 나머지 구독은 남음 |
| 모든 기기 해제 | **모든 기기 알림 끄기** 선택 | 활성 구독 수 0; 테스트/예약 알림 미발송 |
| 다른 사용자 | 별도 사용자로 로그인 | 사용자 간 상태/구독/내보내기 접근 제한 |
| 재구독 | 같은 사용자·기기에서 다시 켜기 | 중복 기기 구독 없이 알림 재수신 |

알림 시간은 Asia/Seoul 기준입니다. DST를 사용하지 않으며 로그 UTC에 9시간을 더해 KST와 비교합니다. 다른 기기의 현지 시간이나 서버 UTC를 직접 예약 기준으로 해석하지 않습니다.

아래에는 현재 사용자 관찰만 반영했습니다. 나머지는 실제 검증 후 채우며, 관찰 없이 완료로 바꾸지 않습니다.
